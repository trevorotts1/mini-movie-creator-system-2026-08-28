# Provider Setup

MMCS talks to providers only through their recorded capability profiles and
adapter packages — never hard-coded model branches. The `.env` variable names
(names only, never values — spec §26 secrets rules) come from `.env.example`
at the repo root; full tables and config-loading rules live in
`docs/installation.md` (§ `.env` configuration).

## Which provider does what

| Concern | Provider | Env names | Notes |
|---|---|---|---|
| Text / reasoning / directing / writing / QC | **Agnes AI** (via 9Router/OpenRouter routing) | `AGNES_API_KEY`, `OPENROUTER_API_KEY`, `NINEROUTER_URL`, `NINEROUTER_KEY` | default director/writer/QC routing |
| Video clips + frames (paid pixels) | **Kie.ai** (Seedance / Wan families) | `KIE_API_KEY` | async jobs, durable task IDs |
| Voice / TTS dialogue | **Fish Audio** | `FISH_API_KEY` | voice profiles, pronunciation lib |
| Durable media archive | **GoHighLevel Media Storage** | `GHL_ACCESS_TOKEN`, `GHL_LOCATION_ID` | see `docs/ghl-setup.md` |
| SFX / voice / music for the legacy `tools/` track | ElevenLabs, Gemini, fal.ai (upstream) | `ELEVENLABS_API_KEY`, `GEMINI_API_KEY`, `FAL_KEY` | required only for the inherited Python track |

## Capability registry — the source of truth

Per-provider limits (prompt character ceilings, reference counts, aspect
ratios, durations, pricing) are mirrored in the machine-readable registry at
`packages/capability-registry/src/data/` (`agnes.ts`, `kie.ts`, `fish.ts`,
`reasoning.ts`) and double-documented in
`docs/provider-capabilities/` — one file per provider family, each value
carrying `lastVerifiedAt` + `sourceUrls` + `confidence` (VERIFIED /
PROVISIONAL / UNKNOWN). **UNKNOWN IS VALID** — never invent a value to fill a
null (e.g. the Agnes prompt character ceiling).

Check what the engine sees:

```bash
mmcs doctor            # which env names are set/missing (names only)
mmcs providers verify  # configured vs documented vs observed capability; never a paid call
mmcs models            # registry view used by planning/validation
```

`mmcs providers verify` never silently rewrites a VERIFIED capability because
of one transient probe failure (spec §24).

## Zero-spend verification before wiring keys

```bash
bash scripts/release/provider-smoke.sh              # report-only, $0 spend gate
bash scripts/release/e2e-dry-run.sh                 # full pipeline, mocked paid steps, real ffmpeg render
```

Both exit 0 with zero credentials absent — they are the credential-gating
smoke (REL-005) and end-to-end dry run (REL-004); committed evidence lives in
`docs/provider-smoke-report.md` and `docs/e2e-dry-run-report.md`
(auto-generated by the scripts — never hand-edited).

## Adding keys

1. Copy `.env.example` → `.env` (if the clean install did not already).
2. Fill in only the providers you use; blank names stay BLOCKED/MOCKED and
   their features fail closed — this is safe, deliberate behavior.
3. `mmcs doctor` → zero missing keys expected for your chosen path.
4. `bash scripts/release/provider-smoke.sh` → each provider you configured
   shows CREDENTIALED; projection and spend stay $0.0000 inside the $25 gate.

Adding a NEW provider family is a code task, not a config task — see
`docs/adding-a-provider.md`.
